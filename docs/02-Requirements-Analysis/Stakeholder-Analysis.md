# School Management System
## Stakeholder Analysis

**Project:** School Management System (SMS)  
**Organization:** Medium-Sized Private School  
**Document Version:** 1.0  
**Date:** October 2026

---

## 1. Introduction

Stakeholder analysis identifies the individuals and groups who influence, interact with, or are affected by the proposed School Management System (SMS).

The purpose of this analysis is to understand stakeholder responsibilities, identify their information needs, and establish appropriate levels of involvement throughout the system development lifecycle.

The system will support the academic, administrative, and financial operations of a single private school through seven integrated management modules.

## 2. Stakeholder Identification

The following table identifies the primary stakeholders and their responsibilities.

| ID | Stakeholder | Responsibilities |
|---|---|---|
| ST-01 | School Principal | Oversees school operations and monitors academic, administrative, and financial performance. |
| ST-02 | System Administrator | Manages user accounts, roles, permissions, and system administration. |
| ST-03 | Administrative Staff | Maintains student records, enrollment information, and class assignments. |
| ST-04 | Teachers | Access assigned classes and manage student academic grades. |
| ST-05 | Accountant | Manages tuition fees, payment transactions, and outstanding balances. |
| ST-06 | Students | Benefit from accurate academic and administrative records. |
| ST-07 | Parents/Guardians | Benefit from accurate academic results and financial information. |
| ST-08 | Development Team | Analyzes, designs, implements, tests, and maintains the system. |

## 3. Stakeholder Needs and Expectations

| Stakeholder | Key Needs and Expectations |
|---|---|
| School Principal | Access to accurate reports, institutional summaries, and reliable information for decision-making. |
| System Administrator | Secure account management, role configuration, access control, and audit information. |
| Administrative Staff | Efficient student registration, record updates, searching, and class assignment management. |
| Teachers | Easy access to assigned classes, student lists, and grade recording functions. |
| Accountant | Accurate fee calculations, payment recording, receipt generation, and outstanding balance tracking. |
| Students | Accurate academic records, grades, and enrollment information. |
| Parents/Guardians | Reliable information regarding student academic performance and financial obligations. |
| Development Team | Clear requirements, defined scope, technical specifications, and acceptance criteria. |

Students and parents are indirect stakeholders and will not have direct system accounts in the initial release.

## 4. Stakeholder Influence and Interest

Stakeholders are classified according to their influence on project decisions and their interest in system outcomes.

| Stakeholder | Influence | Interest | Engagement Strategy |

## 5. Stakeholder Requirements

The following table summarizes the major requirements associated with each operational stakeholder.

| ID | Stakeholder | Requirement |
|---|---|---|
| SR-01 | School Principal | View academic, administrative, and financial reports. |
| SR-02 | System Administrator | Manage user accounts, roles, and permissions. |
| SR-03 | Administrative Staff | Register students and maintain student records. |
| SR-04 | Administrative Staff | Manage class sections and student assignments. |
| SR-05 | Teachers | Record and update grades for authorized classes. |
| SR-06 | Accountant | Manage tuition fees, payments, and outstanding balances. |
| SR-07 | Accountant | Generate payment receipts and financial summaries. |
| SR-08 | School Principal | Access institutional performance summaries. |
| SR-09 | Authorized Users | Securely access permitted system functions. |
| SR-10 | Development Team | Maintain system functionality, security, and data integrity. |

These stakeholder requirements will provide input for the detailed functional and non-functional requirements.

## 6. Stakeholder Engagement Plan

Effective stakeholder involvement is essential for validating requirements and evaluating system usability.

| Activity | Participants | Purpose |
|---|---|---|
| Requirements Review | Principal, Administrative Staff, Teachers, Accountant | Review and refine functional requirements. |
| Security and Access Review | Principal, System Administrator | Validate user roles and permissions. |
| Interface Review | Administrative Staff, Teachers, Accountant | Evaluate usability and workflow suitability. |
| System Testing | Development Team | Verify system functionality and integration. |
| User Acceptance Testing | Authorized School Personnel | Evaluate whether the system satisfies operational needs. |
| Final Approval | School Principal | Approve the system for institutional use. |

## 7. Conclusion

The stakeholder analysis identifies the key individuals and groups associated with the School Management System and establishes their responsibilities, expectations, and levels of involvement.

The School Principal, System Administrator, Administrative Staff, Teachers, and Accountant represent the primary operational stakeholders.

Students and parents are indirect beneficiaries, while the Development Team is responsible for delivering and maintaining the technical solution.

The identified stakeholder needs will guide requirements specification, system design, access control, and acceptance testing.
