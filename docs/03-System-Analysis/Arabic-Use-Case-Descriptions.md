**إصدار المستند:** 1.0  
**التاريخ:** أكتوبر 2026  
**الحالة:** مسودة (Draft)

---

## 1. الغرض من المستند (Purpose)

يصف هذا المستند التفاعلات الرئيسية بين المستخدمين المصرح لهم ونظام إدارة المدرسة (School Management System – SMS).

تحدد كل حالة استخدام هدفًا تشغيليًا، والمستخدم الذي ينفذ العملية، والشروط المسبقة، وسيناريو النجاح الأساسي، والمسارات البديلة، والنتيجة المتوقعة.

وتُكمل هذه الأوصاف المتطلبات الوظيفية دون إعادة صياغة مواصفاتها.

## 2. الجهات المتفاعلة مع النظام (Actors)

| الجهة المتفاعلة | الوصف |
|---|---|
| مدير المدرسة (School Principal) | يراجع المعلومات والتقارير المؤسسية. |
| مدير النظام (System Administrator) | يدير مستخدمي النظام وصلاحيات الوصول. |
| الموظفون الإداريون (Administrative Staff) | يديرون معلومات الطلاب والمعلمين والصفوف الدراسية. |
| المعلم (Teacher) | يسجل درجات الطلاب المصرح له بإدارتها ويراجعها. |
| المحاسب (Accountant) | يدير الرسوم الدراسية ومعاملات الدفع. |

يجب أن يكون جميع المستخدمين قد سجلوا الدخول بنجاح، وأن يمتلكوا الصلاحيات المطلوبة لتنفيذ العمليات التي يطلبونها.

## 4. التوصيف التفصيلي لحالات الاستخدام (Detailed Use Case Descriptions)

### UC-01 — تسجيل دخول المستخدم (Authenticate User)

**المستخدم الأساسي (Primary Actor):** جميع المستخدمين.

**الشروط المسبقة (Preconditions):** يمتلك المستخدم حسابًا نشطًا.

**سيناريو النجاح الأساسي (Main Success Scenario):**

1. يفتح المستخدم واجهة تسجيل الدخول.
2. يُدخل المستخدم بيانات اعتماد صحيحة.
3. يتحقق النظام من بيانات الاعتماد وحالة الحساب.
4. ينشئ النظام جلسة مستخدم موثقة.
5. يعرض النظام الواجهة المصرح للمستخدم بالوصول إليها.

**المسارات البديلة (Alternative Flows):**

- **A1 — بيانات اعتماد غير صحيحة:** يرفض النظام تسجيل الدخول ويعرض رسالة خطأ مناسبة.
- **A2 — حساب غير نشط:** يمنع النظام الوصول ويبلغ المستخدم بأن الحساب غير متاح.

**الشرط اللاحق (Postcondition):** يحصل المستخدم على صلاحية الوصول إلى وظائف النظام المسموح له باستخدامها فقط.

### UC-02 — تسجيل طالب (Register Student)

**المستخدم الأساسي:** الموظف الإداري.

**الشروط المسبقة:** يكون المستخدم قد سجل الدخول ويمتلك صلاحية تسجيل الطلاب.

**سيناريو النجاح الأساسي:**

1. يفتح الموظف نموذج تسجيل الطلاب.
2. يُدخل معلومات الطالب وبيانات الالتحاق المطلوبة.
3. يتحقق النظام من صحة المعلومات المدخلة.
4. يفحص النظام احتمالية وجود سجلات مكررة.
5. يؤكد الموظف عملية التسجيل.
6. ينشئ النظام سجل الطالب ويخصص له معرفًا فريدًا.
7. يعرض النظام رسالة تؤكد نجاح التسجيل.

**المسارات البديلة:**

- **A1 — بيانات ناقصة أو غير صحيحة:** يحدد النظام الحقول غير الصحيحة ويطلب تصحيحها.
- **A2 — طالب مسجل مسبقًا:** يرفض النظام التسجيل وفقًا لقواعد اكتشاف التكرار المحددة.

**الشرط اللاحق:** يُحفظ سجل طالب صحيح في النظام بنجاح.

---

### UC-03 — تحديث معلومات الطالب (Update Student Information)

**المستخدم الأساسي:** الموظف الإداري.

**الشروط المسبقة:** وجود سجل الطالب وامتلاك المستخدم صلاحية التعديل.

**سيناريو النجاح الأساسي:**

1. يبحث الموظف عن سجل الطالب ويحدده.
2. يعرض النظام معلومات الطالب الحالية.
3. يعدّل الموظف الحقول المسموح له بتعديلها.
4. يتحقق النظام من صحة التغييرات.
5. يؤكد الموظف عملية التحديث.
6. يحفظ النظام التغييرات ويعرض رسالة تأكيد.

**المسارات البديلة:**

- **A1 — تغييرات غير صحيحة:** يرفض النظام التحديث ويحدد الأخطاء.
- **A2 — حقل مقيّد:** يمنع النظام تعديل المعلومات التي تقع خارج صلاحيات المستخدم.

**الشرط اللاحق:** يتم تحديث سجل الطالب دون فقدان المعلومات التاريخية المطلوب الاحتفاظ بها.

---

### UC-04 — تسجيل معلم (Register Teacher)

**المستخدم الأساسي:** الموظف الإداري.

**الشروط المسبقة:** يمتلك المستخدم صلاحية إدارة سجلات المعلمين.

**سيناريو النجاح الأساسي:**

1. يفتح الموظف نموذج تسجيل المعلمين.
2. يُدخل المعلومات المهنية وبيانات الاتصال المطلوبة.
3. يتحقق النظام من صحة المعلومات المدخلة.
4. يؤكد الموظف عملية التسجيل.
5. ينشئ النظام سجل المعلم ويخصص له معرفًا فريدًا.
6. يعرض النظام رسالة تأكيد.

**المسار البديل:**

- **A1 — بيانات غير صحيحة:** يطلب النظام تصحيح البيانات قبل إتمام التسجيل.

**الشرط اللاحق:** يصبح سجل المعلم الجديد متاحًا للإدارة من قبل المستخدمين المصرح لهم.

---

### UC-05 — إسناد تكليف تدريسي لمعلم (Assign Teacher)

**المستخدم الأساسي:** الموظف الإداري.

**الشروط المسبقة:** أن يكون المعلم نشطًا، وأن تكون الشعبة الدراسية والمادة المستهدفتان موجودتين.

**سيناريو النجاح الأساسي:**

1. يحدد الموظف معلمًا نشطًا.
2. يختار السنة الدراسية والشعبة والمادة.
3. يتحقق النظام من صحة التكليف المقترح.
4. يؤكد الموظف عملية الإسناد.
5. يسجل النظام التكليف التدريسي.

**المسارات البديلة:**

- **A1 — معلم غير نشط:** يرفض النظام عملية الإسناد.
- **A2 — تكليف غير صحيح أو متعارض:** يمنع النظام العملية ويوضح سبب التعارض.

**الشرط اللاحق:** يُحفظ التكليف التدريسي ويصبح متاحًا للمستخدمين المصرح لهم.

---

### UC-06 — إدارة الشعب الدراسية (Manage Class Sections)

**المستخدم الأساسي:** الموظف الإداري.

**الشروط المسبقة:** أن تكون السنة الدراسية والصف الدراسي المعني قد تم تعريفهما.

**سيناريو النجاح الأساسي:**

1. يفتح الموظف واجهة إدارة الصفوف والشعب.
2. ينشئ شعبة دراسية أو يحدد شعبة موجودة.
3. يُدخل معلومات الشعبة أو يحدثها.
4. يوزع الطلاب المؤهلين على الشعبة.
5. يتحقق النظام من صحة معلومات الشعبة وتوزيع الطلاب.
6. يؤكد الموظف التغييرات.
7. يحفظ النظام المعلومات ويحدّث قائمة طلاب الشعبة.

**المسارات البديلة:**

- **A1 — تكرار معرف الشعبة:** يرفض النظام تعريف الشعبة المتعارض مع معرف موجود.
- **A2 — تعدد الشعب النشطة:** يمنع النظام إسناد الطالب إلى أكثر من شعبة نشطة خلال السنة الدراسية نفسها.
- **A3 — نقل طالب:** ينهي النظام إسناد الطالب النشط السابق، ويسجل الإسناد الجديد، مع الاحتفاظ بسجل الانتقالات.

**الشرط اللاحق:** تبقى معلومات الشعب الدراسية وتوزيعات الطلاب متسقة وصحيحة.

---

### UC-07 — تسجيل درجات الطلاب (Record Student Grades)

**المستخدم الأساسي:** المعلم.

**الشروط المسبقة:** يمتلك المعلم تكليفًا تدريسيًا مصرحًا به، وتكون فترة التقييم مفتوحة.

**سيناريو النجاح الأساسي:**

1. يحدد المعلم الشعبة والمادة المكلف بتدريسهما.
2. يعرض النظام قائمة الطلاب المؤهلين ومكونات التقييم.
3. يُدخل المعلم درجات الطلاب أو يعدّلها.
4. يتحقق النظام من صحة القيم المدخلة.
5. يرسل المعلم الدرجات للحفظ.
6. يحفظ النظام الدرجات ويعرض رسالة تأكيد.

**المسارات البديلة:**

- **A1 — درجة غير صحيحة:** يرفض النظام القيم الواقعة خارج النطاق المحدد.
- **A2 — تكليف غير مصرح به:** يمنع النظام الوصول إلى الشعبة أو المادة المطلوبة.
- **A3 — فترة تقييم معتمدة نهائيًا:** يمنع النظام تعديل الدرجات.

**الشرط اللاحق:** تُحفظ الدرجات الصحيحة للطلاب المحددين ضمن فترة التقييم المعنية.

---

### UC-08 — اعتماد الدرجات نهائيًا (Finalize Grades)

**المستخدم الأساسي:** الموظف الأكاديمي المخوّل (Authorized Academic Staff).

**الشروط المسبقة:** وجود فترة التقييم وامتلاك المستخدم صلاحية اعتماد الدرجات.

**سيناريو النجاح الأساسي:**

1. يحدد المستخدم فترة التقييم والشعبة أو المادة المعنية.
2. يحسب النظام النتائج وفقًا لقواعد التقييم المحددة.
3. يعرض النظام النتائج للمراجعة.
4. يؤكد المستخدم اعتماد الدرجات نهائيًا.
5. يغيّر النظام حالة الدرجات المعنية إلى «معتمدة نهائيًا».
6. يقيّد النظام أي تعديلات لاحقة غير مصرح بها.

**المسارات البديلة:**

- **A1 — درجات غير مكتملة:** يحدد النظام معلومات التقييم الإلزامية الناقصة ويمنع الاعتماد النهائي.
- **A2 — الحاجة إلى إعادة فتح الدرجات:** يبدأ المستخدم المخوّل إجراء إعادة الفتح المعتمد، ويسجل السبب، ويحصل على الموافقة المطلوبة.

**الشرط اللاحق:** تصبح النتائج المعتمدة نهائيًا محمية من التعديلات غير المصرح بها.

### UC-09 — إعداد الرسوم الدراسية (Configure Tuition Fees)

**المستخدم الأساسي:** المحاسب.

**الشروط المسبقة:** وجود السنة الدراسية والصفوف الدراسية المعنية.

**سيناريو النجاح الأساسي:**

1. يفتح المحاسب واجهة إعداد الرسوم الدراسية.
2. يحدد السنة الدراسية والصف الدراسي.
3. يُدخل قيمة الرسوم الدراسية المطبقة.
4. يتحقق النظام من صحة إعدادات الرسوم.
5. يؤكد المحاسب الإعدادات.
6. يحفظ النظام هيكل الرسوم ليصبح متاحًا للاستخدام المصرح به.

**المسار البديل:**

- **A1 — إعدادات رسوم غير صحيحة:** يرفض النظام القيم غير الصحيحة أو الإعدادات المتعارضة.

**الشرط اللاحق:** يصبح هيكل الرسوم الدراسية الصحيح متاحًا لاحتساب الرسوم المستحقة على الطلاب.

### UC-10 — تسجيل دفعة مالية لطالب (Record Student Payment)

**المستخدم الأساسي:** المحاسب.

**الشروط المسبقة:** وجود حساب رسوم للطالب يتضمن رصيدًا مستحقًا.

**سيناريو النجاح الأساسي:**

1. يبحث المحاسب عن حساب الرسوم الخاص بالطالب.
2. يعرض النظام الرصيد المستحق وسجل المدفوعات.
3. يُدخل المحاسب مبلغ الدفع ومعلومات المعاملة المطلوبة.
4. يتحقق النظام من صحة بيانات الدفع.
5. يؤكد المحاسب المعاملة.
6. يسجل النظام الدفعة وينشئ معرفًا فريدًا للمعاملة.
7. يحدّث النظام الرصيد المستحق.
8. ينشئ النظام إيصال الدفع.

**المسارات البديلة:**

- **A1 — مبلغ غير صحيح:** يرفض النظام المبالغ الصفرية أو السالبة أو غير الصحيحة.
- **A2 — دفعة تتجاوز الرصيد المستحق:** يرفض النظام المبلغ الزائد، ما لم تكن هناك سياسة معتمدة تسمح بذلك.
- **A3 — فشل المعاملة:** يلغي النظام العملية غير المكتملة دون تسجيل دفعة جزئية غير مقصودة.

**الشرط اللاحق:** تُسجل الدفعة بدقة، ويُحدّث الرصيد المستحق على الطالب.

---

### UC-11 — تصحيح معاملة دفع (Correct Payment Transaction)

**المستخدم الأساسي:** المحاسب.

**الشروط المسبقة:** وجود المعاملة الأصلية وامتلاك المستخدم صلاحية التصحيح.

**سيناريو النجاح الأساسي:**

1. يبحث المحاسب عن معاملة الدفع الأصلية.
2. يبدأ إجراء تصحيح المعاملة أو عكسها.
3. يقدم المحاسب المبرر المطلوب.
4. يتحقق النظام من صحة الطلب والصلاحيات المطبقة.
5. يتم تأكيد التصحيح المصرح به.
6. يسجل النظام المعاملة التصحيحية.
7. يعيد النظام احتساب الرصيد المستحق على الطالب.

**المسار البديل:**

- **A1 — تصحيح غير مصرح به:** يرفض النظام تنفيذ العملية.

**الشرط اللاحق:** تعكس السجلات المالية التصحيح المنفذ، مع المحافظة على سجل المعاملة الأصلية.

### UC-12 — إدارة حسابات المستخدمين (Manage User Accounts)

**المستخدم الأساسي:** مدير النظام.

**الشروط المسبقة:** أن يكون المستخدم قد سجل الدخول ويمتلك صلاحيات إدارية.

**سيناريو النجاح الأساسي:**

1. يفتح مدير النظام واجهة إدارة المستخدمين.
2. ينشئ حساب مستخدم جديدًا أو يحدد حسابًا موجودًا.
3. يُدخل معلومات الحساب والأدوار المصرح بها أو يحدثها.
4. يتحقق النظام من صحة التغييرات المطلوبة.
5. يؤكد مدير النظام العملية.
6. يحفظ النظام التغييرات ويسجل معلومات التدقيق ذات الصلة.

**المسارات البديلة:**

- **A1 — بيانات حساب غير صحيحة:** يرفض النظام التغييرات ويطلب تصحيحها.
- **A2 — إسناد دور غير مصرح به:** يمنع النظام منح صلاحيات تتجاوز سلطة مدير النظام.

**الشرط اللاحق:** تُحدّث معلومات حساب المستخدم وصلاحياته بصورة آمنة.

---

### UC-13 — إنشاء التقارير (Generate Reports)

**المستخدم الأساسي:** المستخدمون المصرح لهم.

**الشروط المسبقة:** امتلاك المستخدم صلاحية الوصول إلى التقرير المحدد والبيانات التي يعتمد عليها.

**سيناريو النجاح الأساسي:**

1. يفتح المستخدم واجهة التقارير.
2. يحدد نوع التقرير المتاح له.
3. يختار معايير التصفية المناسبة.
4. يسترجع النظام البيانات المصرح للمستخدم بالاطلاع عليها.
5. ينشئ النظام التقرير ويعرضه.
6. يطبع المستخدم التقرير أو يصدره إذا كانت الصيغة المطلوبة مدعومة.

**المسارات البديلة:**

- **A1 — عدم وجود سجلات مطابقة:** يعرض النظام نتيجة فارغة مع رسالة مناسبة.
- **A2 — تقرير غير مصرح به:** يمنع النظام الوصول إلى التقرير أو المعلومات المقيدة.
- **A3 — فشل إنشاء التقرير:** يعرض النظام رسالة خطأ دون كشف معلومات تقنية حساسة.

**الشرط اللاحق:** يحصل المستخدم على تقرير يحتوي فقط على المعلومات المصرح له بالاطلاع عليها.

| UC-02 → UC-06 | يمكن توزيع الطالب على شعبة دراسية بعد تسجيله في النظام. |
| UC-04 → UC-05 | يمكن إسناد تكليفات تدريسية إلى المعلم بعد تسجيله. |
| UC-06 → UC-07 | تحدد الشعب المسجل فيها الطلاب مدى أهليتهم لإدخال الدرجات. |
| UC-07 → UC-08 | تُراجع الدرجات المسجلة قبل اعتمادها نهائيًا. |
| UC-09 → UC-10 | تشكل الرسوم الدراسية المحددة أساس معالجة المدفوعات. |
| UC-10 → UC-11 | قد تحتاج معاملة الدفع المسجلة إلى تصحيح مصرح به. |
| UC-01 → حالات الاستخدام المحمية | يُشترط التحقق من هوية المستخدم قبل الوصول إلى العمليات المحمية. |

تمثل هذه العلاقات **اعتماديات تشغيلية (Operational Dependencies)**، ولا تعني تلقائيًا وجود علاقات `include` أو `extend` وفقًا للغة النمذجة الموحدة (UML).
