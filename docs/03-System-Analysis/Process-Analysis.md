# School Management System
## Process Analysis

**Document Version:** 1.0  
**Date:** October 2026  
**Status:** Draft

---

## 1. Purpose

This document analyzes the operational processes and information flows of the School Management System (SMS).

It identifies process boundaries, inputs, outputs, data stores, and dependencies to support process modeling and subsequent system design.

Detailed user interactions and institutional policies are maintained in `Use-Case-Descriptions.md` and `Business-Rules.md`, respectively.

## 2. Process Identification

The system is organized into seven major operational processes.

| Process ID | Process Name | Primary Responsibility |
|---|---|---|
| P1 | Manage Students | Maintain student and enrollment records. |
| P2 | Manage Teachers | Maintain teacher records and teaching assignments. |
| P3 | Manage Classes | Maintain academic structures and student class assignments. |
| P4 | Manage Grades | Record, calculate, and finalize academic results. |
| P5 | Manage Fees | Assess tuition fees and process financial transactions. |
| P6 | Manage Users | Authenticate users and administer access permissions. |
| P7 | Generate Reports | Produce authorized academic, administrative, and financial reports. |

These processes represent the primary functional decomposition of the system for Level-0 data flow modeling.

## 3. External Entities

External entities represent actors or systems that exchange information with the SMS.

| Entity ID | External Entity | Information Exchanged |
|---|---|---|
| E1 | Administrative Staff | Student, teacher, and class information; operation results. |
| E2 | Teacher | Grade submissions; assigned student and class information. |
| E3 | Accountant | Fee configurations, payment details, and financial results. |
| E4 | School Principal | Report requests and institutional reports. |
| E5 | System Administrator | Account configurations, permissions, and administration results. |

Students and parents are not modeled as direct external entities in the initial release because they do not interact directly with the system.

## 4. Data Stores

The following logical data stores support the identified processes.

| Data Store ID | Data Store | Contents |
|---|---|---|
| D1 | Student Records | Student profiles and enrollment information. |
| D2 | Teacher Records | Teacher profiles and teaching assignments. |
| D3 | Academic Structure | Academic years, grade levels, subjects, and class sections. |
| D4 | Grade Records | Assessment results and grade status information. |
| D5 | Financial Records | Fee structures, student charges, payments, and adjustments. |
| D6 | User and Access Records | User accounts, roles, and permissions. |
| D7 | Audit Records | Records of sensitive operations and changes. |

These are logical stores and do not necessarily correspond to individual database tables.

## 5. Process Input and Output Analysis

| Process | Main Inputs | Main Outputs | Data Stores |
|---|---|---|---|
| P1 — Manage Students | Student details, enrollment updates | Student records, registration results | D1, D3 |
| P2 — Manage Teachers | Teacher details, assignment requests | Teacher profiles, teaching assignments | D2, D3 |
| P3 — Manage Classes | Academic structure definitions, class assignments | Class sections, student rosters | D1, D3 |
| P4 — Manage Grades | Grade entries, assessment definitions, approval decisions | Validated grades, calculated results, finalized records | D1, D2, D3, D4 |
| P5 — Manage Fees | Fee policies, charges, payments, adjustments | Updated balances, payment receipts, financial records | D1, D5 |
| P6 — Manage Users | Credentials, account and permission changes | Authentication results, updated access records | D6, D7 |
| P7 — Generate Reports | Report requests, filters, access permissions | Authorized reports | D1–D6 |

Audit events generated by sensitive operations are recorded in D7 as required by the approved business rules.

## 6. Inter-Process Dependencies

The processes depend on shared institutional data and validated relationships.

| Source Process | Dependent Process | Dependency |
|---|---|---|
| P1 — Manage Students | P3 — Manage Classes | Student records are required for class assignments. |
| P2 — Manage Teachers | P4 — Manage Grades | Teaching assignments determine authorized grade entry. |
| P3 — Manage Classes | P4 — Manage Grades | Class enrollment determines eligible student records. |
| P1 — Manage Students | P5 — Manage Fees | Student identity and enrollment support fee assessment. |
| P3 — Manage Classes | P5 — Manage Fees | Academic year and grade level determine applicable tuition structures. |
| P1–P6 | P7 — Generate Reports | Reports use information maintained by the operational processes. |
| P6 — Manage Users | P1–P5, P7 | Access permissions control protected operations. |

These dependencies describe information relationships rather than mandatory execution sequences.

## 7. Data Flow Modeling

### 7.1 Context Diagram

The Context Diagram represents the entire SMS as a single process interacting with its external entities.

**System Process:** School Management System

**External Entities:** E1–E5

**Primary Data Flows:**

| External Entity | Incoming Data | Outgoing Data |
|---|---|---|
| Administrative Staff | Student, teacher, and class management requests | Registration results, records, and class information |
| Teacher | Grade entries and grade-related requests | Assigned academic information and grade results |
| Accountant | Fee definitions, payment information, and financial requests | Balances, transaction confirmations, and receipts |
| School Principal | Institutional report requests | Authorized institutional reports |
| System Administrator | Account and permission administration requests | Account status and administration results |

The Context Diagram shall not display internal data stores.

### 7.2 Level-0 Data Flow Diagram

The Level-0 DFD decomposes the SMS into processes P1–P7.

Each process shall connect only to the external entities, data stores, or other processes with which it exchanges relevant information.

The diagram shall maintain consistency with the Context Diagram's external data flows.

### 7.3 DFD Modeling Rules

The following conventions apply:

- Processes shall be labeled using action-oriented names.
- Data flows shall be labeled using meaningful data names.
- Data stores shall represent persistent information.
- External entities shall not connect directly to data stores.
- Data shall not flow directly between two data stores without an intervening process.
- The Context Diagram and Level-0 DFD shall preserve consistent external inputs and outputs.

## 9. Process Exceptions

The following exception categories shall be addressed across the modeled processes.

| Exception Category | Expected System Behavior |
|---|---|
| Invalid Input | Reject the operation and identify the required correction. |
| Unauthorized Operation | Deny access and record the event when required. |
| Conflicting Data | Prevent inconsistent changes and preserve existing records. |
| Transaction Failure | Roll back incomplete changes. |
| Missing Required Data | Prevent dependent operations until prerequisites are satisfied. |
| Unexpected System Error | Preserve data integrity and provide controlled error feedback. |

Specific validation conditions and approval requirements are defined in `Business-Rules.md`.
